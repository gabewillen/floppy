# `conversation` implementation report plan

The implementation report plan of [`conversation.scx`](../conversation.scx): the W3C SCXML IRP's
manifest format and `Outcome` oracle over the document's numbered
statements below, one assertion each in [`manifest.xml`](manifest.xml),
tested by the harness documents in [`sources/`](sources). Each harness
invokes the document as its child, drives it, and ends in `pass` (logging
`Outcome` `pass`) or `fail`. `tests/tests/document_irp.rs` runs every case
through `scx run` with the real invoked services (a case's
`backend.json` scripts the fake HTTP backend they reach), and
`tests/irp/harness.py` writes the cases from [`cases.py`](cases.py).

## Statements

- <a id="conversation-1"></a>**conversation-1**. On start it sends `bot.ability.ready` to its parent (decision D242), with no data: it offers nothing.
- <a id="conversation-2"></a>**conversation-2**. A direct `bot.ability.conversation.input` (its parent the envelope `{event: "bot.ability.conversation.input", data}`) or a `bot.ability.conversation.routed_input` `{parent}` (the communication's envelope, whose data is the input) is committed as an inbound message (provenance event the parent's event; no sequence); an inbound commit of text hands the parent `bot.ability.cognition.input` `{stimulus, participants}` whose stimulus is `{event: "bot.ability.conversation.output", data: {parent, messages}, source: "conversation"}`, messages the exchange the commit opens.
- <a id="conversation-3"></a>**conversation-3**. Each input is one turn per source identity (names sorted, then embeddings), each exchanged with its own turn detector; what is committed is the turns' product: their stripped texts joined by spaces, each distinct text once, as `text/plain`; with no text, null content for audio and the input's content otherwise. Its provenance's turn_ref is the first turn's, `input-<n>:turn:<track>`. A commit that is not text answers `bot.ability.conversation.output` `{parent, messages}` itself.
- <a id="conversation-4"></a>**conversation-4**. Each input finds its relationship: targetless input shares the first targetless (ambient) relationship; other input takes the relationship whose source and target groups match, in either direction; with no match it begins its own, whose session_ref is `relationship-` and its context reference `{"identity_groups":[...]}`. The committed provenance's session_ref is the relationship's.
- <a id="conversation-5"></a>**conversation-5**. `bot.ability.conversation.snapshot.request` `{request_ref}`, in any state, answers `bot.ability.conversation.snapshot.output` `{request_ref, detector_refs}`: `[session_ref, source]` of every participant (a source whose detector was ready), ordered by relationship and then identity.
- <a id="conversation-6"></a>**conversation-6**. `bot.ability.conversation.append` `{message}` with an outbound message joins the current exchange and is answered `bot.ability.conversation.output` `{parent, messages}`; one whose provenance id (non-empty), source and target match a message's in the current exchange is not committed again but is answered all the same; an inbound one is not taken (nothing is committed or answered).
- <a id="conversation-7"></a>**conversation-7**. Input that arrives while one is in hand is held (`<event:defer/>`) and taken, in order, on the return to `waiting`.
- <a id="conversation-8"></a>**conversation-8**. A turn the detector cannot close (`bot.ability.turn_detector.failed`) or cannot take (an `error.*`: a start its schema refuses) answers `bot.ability.conversation.failed` `{stage: "turn_detector", message}` and commits nothing.
- <a id="conversation-9"></a>**conversation-9**. With a `memory` param (decision D266) it recalls the relationship's memories before the turns and remembers the input after them through the memory ability, then commits as without one; a memory failure answers `bot.ability.conversation.failed` `{stage: "memory", message}` and commits nothing.
- <a id="conversation-10"></a>**conversation-10**. An input its schema refuses is never routed here: the send raises `error.execution` in the sender, and nothing is committed.
- <a id="conversation-11"></a>**conversation-11**. Every output is the current exchange (decision D176), never the cumulative history: an inbound commit opens a new exchange, `[the inbound message]`, its input the exchange's `parent`; each outbound commit joins it; the next inbound replaces it, and nothing earlier is carried.
- <a id="conversation-12"></a>**conversation-12**. Every message carries `participants`, stamped by its producer and never inferred: an inbound message the turn's participants as `<conversation:turn_participants>` stamps them (its string source ids as `{ref, role: "source"}`, then its string target ids as `{ref, role: "target"}`; an embedding is no ref), which the cognition handoff carries too; an outbound message those its append carries (`[]` when it carries none).
- <a id="conversation-13"></a>**conversation-13**. With a `memory` param, an input with a voice embedding among its identities is identified through long-term memory first (decision D194): each embedding is the person memory holds whose voice it matches (cosine at 0.85, margin 0.05, as relationships match), else a new person `person-<n>`, and the person's ref takes the embedding's place, so the relationship, the turns, the participants and the committed message key on the person; every voice heard is stored for its person. Without one an embedding is its own participant, its track `track-` and its unit vector. A memory failure there answers `bot.ability.conversation.failed` `{stage: "memory", message}` and commits nothing.

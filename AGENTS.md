# Project rules

These rules are normative for every contributor to this repository, whether a
human or an AI coding agent. MUST, SHOULD, and MAY are used as in RFC 2119.
[docs/decisions.md](docs/decisions.md) records why they are what they are, and
[docs/port-plan.md](docs/port-plan.md) maps the original onto floppy.

## Repository and the scxml.rs subtree

- floppy MUST run bots only as SCXML machines executed by the scxml.rs engine inside the generic `scxml-machine` Wasm component; floppy code MUST NOT select transitions, implement macrosteps or microsteps, or duplicate any engine semantics.
- floppy has no runtime of its own (decision D14): it is bots (SCXML documents and their schemas) and packages (`namespaces/*`, `services/*`), and they run with scxml.rs's `scx run`. floppy MUST NOT add an embedder, session loop, config format, or other host code; a capability a bot needs from the runtime MUST be added to scxml.rs upstream (through its own review) and arrive through the subtree.
- `scxml.rs/` is a squashed git subtree of scxml.rs (its source branch and commit are recorded in [docs/decisions.md](docs/decisions.md)). Its own [AGENTS.md](scxml.rs/AGENTS.md) is normative for every change inside it, and a change there MUST go upstream to scxml.rs first (through its own review) and arrive here only through `git subtree pull --prefix scxml.rs <scxml.rs> <branch> --squash`; contributors MUST NOT edit files under `scxml.rs/` in this repository.
- The floppy Cargo workspace MUST exclude `scxml.rs` and depend on its crates by path; it MUST NOT absorb scxml.rs's workspace, lockfile, or members.
- The workspace MUST remain on Rust `1.98`, edition `2024`, and Cargo resolver `3` (matching scxml.rs) unless an explicit reviewed migration changes all authoritative metadata and proof together. `Cargo.lock` MUST remain committed; shared dependencies MUST resolve to the versions scxml.rs's `Cargo.lock` pins (it was seeded from it).
- Canonical extension namespaces live as crates under `namespaces/<name>/` (today `decision`, `bot`, `conversation`, `migration`), canonical invoked services under `services/<name>/`, bots as SCXML documents under `bots/<name>/` (the bot root `bots/<name>/<name>.scx`, its event contracts in `bots/<name>/schemas/`), shared ability documents under `abilities/` (`abilities/<ability>/<ability>.scx`, canonical contracts in `abilities/schemas/`; decision D33), and the integration tests (which drive `scx`) under `tests/`. Every bot and ability document MUST be `<name>/<name>.scx` with its ECMAScript in `<name>/<name>.js` beside it (decision D65). An `event:schema` reference MUST stay inside its document's directory (no `..`), so each event schema an ability references is a byte-identical twin in `abilities/<ability>/schemas/` of its `abilities/schemas/` source, and an ability event the body receives is a byte-identical twin in `bots/<name>/schemas/` (decision D37). Their repository URIs MUST be exactly the tagless `https://github.com/stateforward/floppy/namespaces/<name>` and `https://github.com/stateforward/floppy/services/<name>`, which are each package's identity, and their manifests (and a namespace's schema `targetNamespace`) MUST name that tagless URI (decision D21). A document MAY pin a release by writing `@<tag>` after the URI in an `xmlns` declaration or a literal `<invoke type>`; that tag is split off once, when scxml.rs parses the document, and is resolution input for `scx`'s resolver only, never part of the namespace: everything else sees the tagless URI, exactly.
- The SCXML authoring namespace is scxml.rs's `scx` namespace (`https://github.com/stateforward/scxml.rs/namespaces/scx`, `<scx:validate>`), which `scx` embeds; documents bind it with the prefix `scx`, and floppy MUST NOT ship its own copy.
- Versions of scxml.rs contracts MUST stay at WIT `@0.2.0` and Machine IR `5` until scxml.rs releases a change; floppy MUST NOT bump them on its own.

## Components

- Namespaces and services MUST be independently deployable Wasm components behind scxml.rs's versioned WIT contracts (`stateforward:scxml/executable-content-extension`, `stateforward:scxml/invoked-service`), built for `wasm32-wasip2` by `scripts/build-components.sh` with the reproducible release flags, virtualized by the pinned `wasi-virt`, validated by the pinned `wasm-tools`, and checked against an exact per-component import allowlist.
- New component crates, worlds, and artifacts MUST use concise domain names and MUST NOT add a redundant `-component` suffix.
- Package manifests (`stateforward.scxml.extension-package/v2`, `stateforward.scxml.service-package/v1`) MUST bind the exact URI, package version, component artifact, schema artifact and SHA-256 where one exists, WIT world and version; a service package also MUST declare its outbound HTTP origins and `env` slots, which an extension package never declares (an extension does no I/O); either MAY name a package validator component (`validator-artifact`, `validator-sha256`: the `generate` package's is `services/generate/validator`, decision D27); nothing else (no WASI, no events: scxml.rs refuses unknown fields). The events a service returns are described by the invoking document with `event:schema` on the transitions that take them (the builder describes `generate.*` and `decision.*` that way), and a service MUST validate every event it returns itself (the `decision` service checks the chosen event's data against the choices' schema for it; its own events are correct by construction). Unknown, non-canonical, or over-bound declarations MUST fail closed.
- Anything asynchronous, I/O-bound, or long-running (model calls, network requests, storage, devices) MUST be an invoked service (`<invoke>`). Extension elements are executable content, which SCXML runs synchronously inside a microstep, so they MUST stay quick and MUST NOT perform I/O: model calls MUST NOT run inside executable content, and extension components get no `outbound-http`, no WASI, and no `env` slots (scxml.rs removed them from the extension world and manifest; `env:` is valid only on a service's `<invoke>`). This is the rule, not a gap. A service is one async `invoke` export (WASI 0.3, the Component Model async ABI): it awaits `outbound-http.fetch`, an `async func` that suspends only its own task, so a request never blocks the session; its time bounds live in the topology (a `<send delay>` in the invoking state, whose exit cancels the invocation and closes its connection, SCXML 6.4).
- A service MAY import WASI interfaces; what it may use is exactly what its component imports. Runtime resources are granted by the run with wasmtime CLI's option names scoped to the service URI (`--dir URI=HOST::GUEST`, `--wasi URI=inherit-network`, `--wasi URI=allow-ip-name-lookup`); `scx run` fails closed before the session starts when an imported resource is ungranted, a grant has no matching import, or the component imports a `wasi:*` interface the host never links, and lists every service's WASI imports and granted resources before running. A bot's README gives the grants its services' imports need (the generate service imports `wasi:filesystem` to read the images a message names, and the speech service to read and write sound, so every run that binds either grants it a media directory: `--dir https://github.com/stateforward/floppy/services/generate=HOST::/media`, `--dir https://github.com/stateforward/floppy/services/speech=HOST::/media`).
- Components MUST NOT receive secret values: elements and `<invoke>`s name variables for declared slots with the `env` attribute vocabulary, and only the host substitutes values into admitted requests.
- Event contracts MUST use scxml.rs's `event:schema` vocabulary, referenced as schema files (`event:schema="schemas/<event>.json"`), never inline. scxml.rs checks them where an event is created (a `<send>` or `<raise>` that fails raises `error.execution` in the sender), on sends between sessions, and on host input (`scx run` refuses it as `machine-invalid-input`) (decision D41); transitions still match by name. What scxml.rs does not check is enforced by the `decision` service (candidates are the enabled transitions and their schemas, which `<decision:choice>` reads through `session-snapshot-host` and writes as the canonical choices; the chosen event's data is filled to its schema and validated before it is returned) and by each service, which validates what it returns.
- Model backends MUST stay pluggable through `env` slots (`env:baseurl`, `env:apikey`); no key may be compiled into a component, and the only backend URL a service uses without a `baseurl` value is its package's first declared `http-origins` entry, read from the manifest it ships (decision D18), never a second copy. The `generate` service declares none, so it has no default backend: a run MUST hold `FLOPPY_BASE_URL` and `FLOPPY_API_KEY`, and without either it sends nothing and answers `unconfigured` (decision D31). The `speech` service declares none either: its operations reach only the backends a run names (`FLOPPY_SPEECH_BASE_URL` and `FLOPPY_SPEECH_API_KEY` for speech, `FLOPPY_VOICE_BASE_URL` and `FLOPPY_VOICE_API_KEY` for voices; decision D57).

## Bots

- A bot MUST run as `scx run --env-file <file> bots/<name>/<name>.scx` with nothing else against a release but the `--dir` grants its services' imports need, or with `--offline --cache-dir target/components/package-cache` against the packages `scripts/build-components.sh` builds (a dev cache under `target/`; a dev build MUST NOT write `scx`'s release cache): its namespaces and `<invoke type>`s are the packages' tagless repository URIs, so the same document resolves in both, its `env` attributes scope the variables, other documents load through `<invoke src>` by URI (relative to the document, `file:`, or `https:`), and it reports its result through the `<donedata>` of its top-level final states (SCXML 6.4: `done.invoke.<id>` when invoked). Its README MUST give the exact command. Repository-authored SCXML documents use the extension `.scx`.
- A bot MUST be an SCXML document; its abilities MUST be invoked children (`<invoke type="scxml">`) or invoked services, and its devices MUST be SCXML documents its environment invokes, any I/O a device does being an invoked service inside it (decision D105). The original's attachment protocol MUST NOT be ported: invoke lifecycle covers attach and detach.
- Domain event names (`bot.*`, `bot.ability.*`, `phone.*`) MUST stay byte-for-byte as the original names them.
- Bot and ability documents (`bots/floppy/`, `abilities/`) MUST follow the document structure rule (decision D39): one `.scx` per the original state machine, invoked by a literal `id` and a literal relative `src`; the bot root only composes; reusable synchronous logic is a namespace element that writes to a `location`, and I/O is an invoked service. Each loads its ECMAScript through exactly one root `<script src="<name>.js"/>` (SCXML 5.8) and contains no other `<script>` and no `function` (decision D65): every `cond` and every `expr` outside `<data>` that is more than a literal, an identifier, or a dotted path calls a function of `<name>.js`, which reads the data model and returns a value (state changes stay `<assign>`), each at most 160 characters. Builder output and the documents a `srcexpr` or `<content expr>` invokes have no directory of their own, so they carry no `<script>`. Payloads MUST be checked by `event:schema` only (decision D42): a `cond` correlates (which turn, which run, which timer) and MUST NOT re-check a payload's shape, except for events scxml.rs does not check (`done.invoke.<id>` donedata and an invoked service's events). A transition MUST be routed by its event descriptor and the state it is in: a `cond` MUST NOT test `_event.name`, and MUST NOT test `_event.invokeid` except where decisions D81 and D82 say SCXML cannot express it (a re-entered state's `idlocation` id, a builder simulation's untrusted child); a child's failure is taken by its name, `error.communication.<invokeid>`. `tests/tests/contracts.rs` enforces these rules.
- Retries, timeouts, and bounded loops MUST be modelled in the topology (states, `<send delay>`, counters in the data model), never in ad hoc host or component code. A timeout on an invoked service MUST be able to preempt it: arm it in the invoking state and leave that state when it fires, which cancels the invocation.
- The builder bot builds SCXML only (never Rust): its drafts MUST pass `scx:validate` and a simulation as an invoked child before it ends in its final state `done`. The builder MUST NOT restrict what a draft may use (decision D28): what a draft can do when simulated is bounded only by the run's own consent and grants, as for any document.

## Engineering

- Production code MUST NOT use unhandled `unwrap()`, `expect()`, `panic!()`, `todo!()`, `unreachable!()`, indexing known to panic, unchecked conversions, or ignored `Result` or `Option` values on reachable input or runtime paths; tests MAY use `expect()` with a message that states the invariant.
- Expected failures MUST use typed errors with preserved safe context and MUST fail closed at trust boundaries; unknown fields, versions, enum values, and capability kinds MUST be rejected rather than ignored.
- Every crate root MUST carry `#![forbid(unsafe_code)]` wherever target or generated-binding constraints permit; authored unsafe code MUST NOT be added.
- Resource bounds a document can reach (sizes, counts, fuel, loop iterations) MUST apply to wasm builds only, declared through `scxml_types::wasm_bound`; input-file bounds at the embedder's trust boundary (env files, manifests, components; all read by scxml.rs) MAY apply on every build, and retries and waits MUST have explicit upper bounds.
- Core logic MUST receive clocks, randomness, filesystems, networks, environment, and storage through explicit capability boundaries; only the embedder (scxml.rs's `scx`) reads files and env files.
- Secrets MUST NOT be printed, logged, formatted into errors, copied, or committed. Keys reach a run only through `scx`'s `--env-file` (or the calling shell, for a variable a bare `--env NAME` names), and only the elements and `<invoke>`s whose `env` attributes name a variable receive it; commands and documents MUST NOT carry secret values (`--env NAME=VALUE`); `.env*` files are ignored by git.
- Production code MUST emit OpenTelemetry at its boundaries (component entry points through scxml.rs's telemetry WIT facade in guests; the native runtime's telemetry is scxml.rs's); every metric dimension and attribute MUST have a documented bounded-cardinality analysis, and paths, URIs, event or state names, payloads, values, and digests MUST NOT be indexed attributes.
- Pre-1.0, undeployed replacements MUST be hard cutovers that remove the old path, tests, configuration, and documentation in the same change; compatibility shims and legacy fallbacks MUST NOT be added.
- Changes MUST be narrowly scoped and supported by tests matching the exact claim. Before claiming completion, contributors MUST run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` (whose `tests/` crate builds the components and `scx` and runs every bot, namespace, and service through `scx run`), and `sh scripts/build-components.sh` for component changes.
- Contributors MUST NOT use the `find` command in this repository's tooling or agent workflows; use `rg` and `ls`.
- AI agents MUST NOT create commits, amend commits, push, create remotes, open pull requests, or merge unless the maintainer directing the work explicitly requests the exact action; when commits are requested they MUST be local, atomic, and on the named branch only.

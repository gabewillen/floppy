## Rules For Every Slice

* read `docs/handoff.md`, `docs/decisions.md` and `AGENTS.md` before the first slice of a session; trust them over `docs/port-plan.md`
* write bots, abilities, behaviors, routines and policy as SCXML in `.scx` files; justify every non-.scx artifact in the slice's commit message
* allowed non-.scx artifacts: JSON Schema files (`event:schema` sources), READMEs, saved example runs, Rust test code under `tests/`, the floppy namespace components named in [Document Structure Map](#document-structure-map) (`namespaces/decision`, `namespaces/bot`, `namespaces/conversation`: synchronous executable content only, no I/O), and the I/O services under `services/`
* follow the DOCUMENT STRUCTURE user answer in every slice: one `.scx` per mosfet state machine, invoked by a literal `id` and a literal relative `src`; payload checks by `event:schema` only; reusable synchronous logic as floppy namespace elements that write to a `location`; I/O as invoked services; the bot root only composes; ECMAScript only as short `cond`/`expr`/`location` expressions (no `<script>` blocks, no `function` definitions)
* keep every cross-document `<send>` visible in the `.scx` (namespace elements compute and assign; they never send), so the contract test and `EVENT011` still see every boundary
* keep every mosfet event name byte for byte; floppy-only names are marked `[floppy name]`
* do not port the attachment protocol (D6), yamux, define/start/address/scope/lifecycle/cli plumbing, the studio publishing, or the dashboard control plane
* keep devices, phone, speech, vision, Listening, Reading and TurnDetector out of phase 4; keep Autonomy behaviors, Reflection, Revision, Routines and Learning as declared seams only (phase 5)
* model every memory step as an honest seam: a real state that raises its mosfet result event with `memory:"absent"` and empty results, logs `<log label="memory" expr="'absent'">`, and never fabricates recall; phase 3 replaces the raise with an `<invoke>` of `services/memory`
* never edit `scxml.rs/` inside floppy; any scxml.rs change goes to `~/VSCode/stateforward/scxml.rs-services` on `feat/invoke-services` only after the user approves its names
* never run `find`; use `rg` and `ls`
* never print or commit `.env` values
* commit locally and atomically after each slice's full proof is green; never push
* the full proof is `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, plus `sh scripts/build-components.sh` when a component changed
* the live proof prefix is `FLOPPY_LIVE_ENV_FILE=.env:$HOME/VSCode/stateforward/mosfet/mosfet.py/.env FLOPPY_LIVE_MODEL=Qwen/Qwen3.8-Flash-Next`; live tests print pass or fail only
* if a slice's proof stays red after a root-caused fix, go to [Handle Blocked Slice](#handle-blocked-slice)

## Document Structure Map

Restructure design (2026-10-09), from three read-only maps of mosfet.py, floppy's phase 4 documents, and scxml.rs invoke/service/namespace capabilities. It applies the DOCUMENT STRUCTURE user answer.

What "SCXML services" means here: scxml.rs has no SCXML-implemented service package. A `services/<name>` package is always a Wasm `invoked-service` component, and its manifest cannot point at a `.scx` file. So each mosfet machine is mirrored as an SCXML child session (`<invoke id="<literal>" type="scxml" src="<relative file>">`). That is SCXML's own service mechanism. The child's lifecycle (invoke start, cancel on exit, `done.invoke.<id>`, `#_parent`/`#_<id>`) replaces mosfet's Ability lifecycle and attachment protocol. Each mosfet provider becomes a Wasm service. Packaging a `.scx` file as a versioned repository service would need new scxml.rs names; it is not proposed.

Mapping rules, by mosfet pattern:

* Ability = outer lifecycle + inner submodel: only the submodel is written as a `.scx`. The lifecycle is the invoke lifecycle, and `attachment.Group` is the body's set of parallel `<invoke>`s joined on the first `bot.ability.offers` from each.
* "apply" abilities (idle → applying around a provider): the provider is an invoked Wasm service and the two-state wrapper disappears into the `<invoke>`.
* `Processing` (Intuition, Reasoning, Reflection, Revision): the processor is the `decision` or `generate` service. Choosing events is a decision-namespace element. Dispatching the chosen events is a visible `<foreach>`/`<send>`.
* Operation machines (`_ProcessingOperation`, `_AttachmentOperation`, hop and reply operations): `<send delay id>`/`<cancel>` plus sendid and turn guards in the owning document. No `.scx` file of their own.
* Memory (called directly in mosfet): the phase 3 `services/memory` invoked service. Until then it is the honest seam state.
* Helpers (`attention_bias_for_turn`, envelopes, `model_facing_event_json_schema`, `collect_offered_events`, `_resolve_target`, `_selection_item_branch`, `ConfidenceTuner`, conversation message commit): floppy namespace elements.
* Validators: `event:schema` on the receiving transition. This is blocked until scxml.rs enforces `event:schema` at runtime, because today it is metadata only (`scxml.rs/namespaces/event/README.md` "Metadata only"; `EVENT010`/`EVENT011` "the transition is still taken"). See [Enforce Event Schemas At Runtime In scxml.rs](#enforce-event-schemas-at-runtime-in-scxmlrs).

* 2026-10-09 (Add Choice Compaction Element): the body's `compactSchema`/`compactChoices` and reasoning's `dataSchema` stay until [Move Choice Assembly And Routing Into The Decision Namespace](#move-choice-assembly-and-routing-into-the-decision-namespace) and [Move Selection Schema And Confidence Tuner Into The Decision Namespace](#move-selection-schema-and-confidence-tuner-into-the-decision-namespace), whose texts now name them. Byte-identical traces (a done-when condition) win over the grep condition
* 2026-10-09 (Add Choice Compaction Element): the bound is measured as canonical JSON UTF-8 bytes (at least `JSON.stringify`'s UTF-16 length, equal for ASCII), since the limit it protects (spike (b)) is a byte bound; `overlocation` is always assigned (true or false) so the document never reads a stale flag; entries with keys other than `event`, `schema`, `description`, `target`, or with a non-string description or empty target, are `error.execution` (the scripts silently dropped them; a malformed offer is a document bug)

* 2026-10-09 (Move Choice Assembly And Routing Into The Decision Namespace): `<decision:route>` writes ONE ordered list (`{event, data, target}` or `{dropped}`) instead of the slice text's `location` + `droppedlocation`, because two lists cannot keep the interleaved `bot.route`/`bot.route.dropped` log order the pinned traces require.
